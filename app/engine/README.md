# Brain Engine

Brain Engine is a fork of [llama.cpp](https://github.com/ggml-org/llama.cpp), created to give better flexibility when using AI models. It is not an official llama.cpp build.

It is llama.cpp at the tag in `package.json` (`bundledLlamaTag`) with the patches in `engine/patches/` applied in order:

- `0001-expert-mask.patch`: turn a mixture-of-experts brain's experts on or off without reloading it. Engine: `llama_set_expert_mask()`. Server: `GET /expert-mask` and `POST /expert-mask` with `{"keep": null}` (all on), `{"keep": [ids]}` (the same experts in every layer) or `{"keep": [[ids], null, ...]}` (one list per layer, null = all). Each layer keeps at least as many experts as the brain uses for each word. A change clears the cached prompts. It is refused while the server is answering.
- `0002-expert-trace.patch`: report which experts a mixture-of-experts brain picked (`"kind": "experts"`). For a brain with no experts the same request reports groups of neurons instead (`"kind": "neurons"`): each layer's hidden feed-forward neurons, after the activation, are cut into 256 equal runs (`n_expert`; `n_ff` is how many neurons that slices) and the 8 with the highest mean square are listed for every token, busiest first (`n_expert_used`). Server: `"expert_trace": true` on `POST /completion` adds `expert_trace` to the answer: `rows`, one for every token the brain read, in order, each `{"t": the token's text, "e": [[expert ids] for each layer]}`; `n_prompt`, how many of the rows are the prompt (the rest are the answer's own tokens read back, and the experts lit while reading a token are the ones that wrote the next); `last`, the final token written; and `n_layer`, `n_expert`, `n_expert_used`. The last layer is only worked out where an answer is wanted, so its list is empty for the prompt's earlier tokens. The trace is only given to a request that had the brain to itself (ask one at a time); with `stream` it comes with the final piece; `POST /v1/chat/completions` carries it the same way. While a request asks for it the brain is computed step by step, which is slower; nothing changes for requests that don't ask. Engine: `llama_set_eval_callback()`, to set or clear the eval callback of a live context. Bob's Lab uses it for Peek inside's live view and for FNRI. With `"expert_trace_heads": true` as well, any model reports its attention heads instead (`"kind": "heads"`): the attention output of every layer (`kqv_out`) is cut into its `n_head` heads and the busiest (a quarter of them, at most 8) are listed. Neuron and head traces also carry `"a"` on every row: the mean square of the whole node for each layer, which Bob's viewer shows as Floors only.
- `0003-dials.patch`: turn a part of a brain up or down without reloading it. A dial multiplies what one part adds to the stream, which is the same as scaling that part's output weights: one expert of a layer, one attention head of a layer, a layer's whole attention, or a layer's whole feed-forward block. Engine: `llama_set_dials()`. Server: `GET /dials` and `POST /dials` with `{"dials": null}` (everything back to 1) or `{"dials": [{"kind": "expert" | "head" | "attn" | "ffn", "layer": 0, "index": 0, "scale": 0.5}, ...]}` (scale 0 to 8; `index` is the expert or head number). Refused while a slot is busy; prompt caches are cleared on a change. The expert trace reports what the brain does with the dials set. FNRI's Dials use it.
- `0004-rpc-wifi.patch`: card sharing (Bob-Net's "Lend my graphics card") re-sends almost nothing on a reload, which matters most over Wi-Fi. The lent card's server (`ggml-rpc-server -c`) keeps every weight it was sent; upstream only offers it a weight's hash first for weights over 10 MiB, so a mixture-of-experts brain's many 1 to 10 MiB weights (attention, shared experts) went over the network again on every load. Brain Engine offers the hash for every weight over 1 MiB (`GGML_RPC_HASH_MIN` in bytes changes it). Any rpc-server answers a hash of any size, so this works with plain llama.cpp lenders too. And `ggml-rpc-server --seed FILE.gguf` (more than one may be given) fills that store from a copy of the brain on the lending machine, at disk speed, then exits: each weight over the same size goes in under the name a load asks for, written whole or not at all. It prints `seed: <done>/<total> <file>` lines and exits 0 when every file was seeded. A weight's name is its hash, so a seeded file only ever stands in for the exact same bytes.

- `0005-scut.patch`: SCUT (Signals and Communications - Universal Transceiver), Bob's own link for card sharing over Wi-Fi. Opt-in on both ends (`GGML_RPC_SCUT=1`); the two sides agree on it in the RPC `HELLO` through the connection-caps field (the same field RDMA uses, so it is never offered when RDMA is), and stay on plain TCP whenever either side doesn't offer it or the UDP path doesn't answer. The RPC commands are unchanged; only how their bytes travel is. The data goes as UDP datagrams with sequence numbers, selective acks (up to 64 ranges) and resends after a few milliseconds measured from the round trip, instead of TCP's 200 to 300 ms timeout after a lost packet at the end of a message. It paces itself with a token bucket at the rate it measures being delivered, under a cap (`GGML_RPC_SCUT_MBPS`, default 300; Bob sets 50, 100 or 300), and backs off when more than 5% is lost in a round trip or the round trip grows, so it doesn't crowd other devices. While words are flowing it sends a 20-byte ping every 25 ms so a handheld's Wi-Fi doesn't doze (`GGML_RPC_SCUT_AWAKE=0` stops that). The UDP side binds the same port number as the server's TCP port; behind a relay, `GGML_RPC_SCUT_PUBLIC_PORT` names the relay's port in the offer (Bob's gate passes UDP on 50052 to the card server's 50053). The TCP connection stays open as the liveness line. SUDDAR (Signal and Uplink Delay Detection and Ranging) is the probe at the start: the client pings the UDP path up to 10 times and times it before both sides switch. Over a simulated Wi-Fi (3 ms, 1% loss) words went from about 9 to about 15 a second, with byte-identical output.

The patches change only llama.dll / libllama and llama-server, never ggml or the card backends, with one exception: `0004` and `0005` change the card-sharing backend (`ggml-rpc.dll` / `libggml-rpc.so`), which is not a card backend and ships in the Brain Engine download. So a Windows Brain Engine is the official CUDA or Vulkan zip for the same tag with `llama.dll`, `llama-server.exe` and the other `llama*`/`mtmd` files swapped for the ones built here. It also carries two tools the official zips leave out (upstream skips them when the card backends load at run time), each built CPU-only as one self-contained file:

- `llama-cvector-generator`: the Lab's "Take out the refusal habit".
- `llama-export-lora`: the Lab's teach step, to fold a taught adapter into a brain file.

And four tools Bob runs beside the server, built from the same tag in the main build (they use the llama files above):

- `llama-bench`: the standard speed test (the Lab's Challenges, "Add the standard speed test").
- `llama-gguf-split`: joins a brain that comes in parts into one file (the Lab's "Bring in a full-size brain"), and splits one for an upload over Hugging Face's 50 GB limit.
- `ggml-rpc-server`: Bob-Net's "Lend my graphics card", so one brain can spread over several of your Bobs' cards. Bob starts it only when a paired Bob asks through the passcode door, binds it to 127.0.0.1 behind a gate that lets in only the asking Bob's address (on the home network when both are on it, else on this machine's Tailscale address; never 0.0.0.0), and stops it when that Bob lets go, after 3 minutes with no word, or when Gaming starts. The RPC server has no passcode of its own, which is why it is never left open.
- `llama-diffusion-cli`: runs diffusion brains (Dream, LLaDA, RND1) in the Lab's Playground. The official llama.cpp downloads don't have it (their builds leave the examples out), so it needs `-DLLAMA_BUILD_EXAMPLES=ON`.

The build turns on `-DGGML_RPC=ON` so the card server exists. Its `ggml-rpc` backend file is Brain Engine's own (patch 0004). The other ggml files are never swapped.

The **Brain Engine** workflow (`.github/workflows/brain-engine.yml`) builds them when `engine/` changes, or by hand.
